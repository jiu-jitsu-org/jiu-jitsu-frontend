# 타입(scope): 간결한 제목 (50자 이내)
#
# 상세 설명 (선택사항, 필요시 작성)
# - 무엇을 변경했는지
# - 왜 변경했는지
# - 어떤 영향이 있는지
#
# 관련 이슈 (이슈 번호 입력)
# Closes #
# Fixes #
# Refs #
#
# =============== 작성 가이드 ===============
# 타입:
#   feat      - 새 기능 추가
#   fix       - 버그 수정
#   docs      - 문서 변경
#   style     - 코드 스타일 변경 (동작 변화 없음)
#   refactor  - 코드 리팩토링
#   test      - 테스트 추가/수정
#   chore     - 빌드/설정 변경
#
# scope (선택):
#   - 변경된 기능/영역을 소괄호로 표기 (생략 가능)
#   - 예: feat(auth), refactor(policies), feat(workflow)
#   - 전반적 설정/문서 변경은 scope 없이 작성 (예: docs:, chore:)
#
# 제목 작성 규칙:
#   - 50자 이내로 간결하게
#   - 명령문으로 작성 ("추가" O, "추가했다" X)
#   - 영문 시작 시 첫 글자 소문자
#   - 마침표 없음
#
# 이슈 연결:
#   - Closes #123: 이슈 자동 완료
#   - Fixes #123: 버그 수정시 사용
#   - Refs #123: 이슈 참조만
#
# 예시:
#   feat(auth): 웹뷰 인증/세션 + 네이티브 브릿지 기반 구축
#   feat(policies): 마케팅 정보 수신 동의 페이지 추가
#   refactor(policies): service 피처에서 policies 피처로 분리
#   fix: 최신 워크플로 + PR 템플릿 동기화
#   docs: PR 템플릿 간소화
# ==========================================
